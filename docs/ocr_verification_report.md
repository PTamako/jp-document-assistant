## 测试结论

**Cloudflare Workers AI 真实请求已发起，但识别准确率尚无法验证。** 通过当前连接的 Cloudflare 账户，使用 `POST /accounts/{account_id}/ai/run/@cf/moondream/moondream3.1-9B-A2B` 对一个公开的日本收据图片 URL 进行了两次只读 AI 推理请求（不创建/修改 Worker、D1、R2）。请求返回 `success: true`、`errors: []`，但模型返回的 `result` 均为 `{}`，没有提取文本、金额或可供逐字段对照的结果。`GET /ai/models/schema?model=...` 成功返回了 `task=query / image / question` 输入 schema，以及 `answer`、`metrics` 输出 schema。因此**不能将 HTTP 成功状态视作 OCR 识别成功，更不能捏造准确率或推理耗费**。可能存在模型执行或连接器响应包装问题；没有直接可见的原始模型输出，根因尚未证实。

**这不证明 OCR 不可用，也不证明 OCR 可用**；它证明当前路径尚未完成端到端验证。为节省现有三个 App 共用的 Workers AI 免费额度，没有无限重试或更换多个模型重复计费。所有生产资源未修改，未新建 Preview。

## 推荐复测步骤（不触及生产 D1/R2）

1. 取得 **许可适用**且已经永久遮盖个人信息的原图与字段 ground truth；首批至少：收据 10、工资单 5、缴费单 5、信用卡通知 5、活动/使用说明/法规 5，包含小字、倾斜、模糊、长表、两页。工资/缴费/法规最好由本人授权样本人工遮盖并手工校准字段。
2. 先检查文档是否有可用文字层；有文字层直接结构化提取，不走 OCR。对扫描件，统一输出 `raw_text_ja`、`amount_jpy`、`due_date`、`payment_state`、`source_quote`、`review_required`，明确 `null` 与未知值。
3. 为视觉模型和浏览器端免费 OCR（如适用的本地引擎）分别建立同一批样本，固定同样预处理参数/输入长边/模型版本；逐图最多 1 次初始请求，失败后记录错误而不是无限重试。切换图像编码时对照原图证据，强制保留工资数字和日期清晰度。
4. 记录完整模型输出、实际费用计量（Neurons）、延迟和结果；只在本地临时测试环境保存脱敏数据。评分：金额完全匹配率、到期日准确率、已付/未付分类准确率、字段漏检率、需人工复核比例、AI Neurons/张；错误金额/支付状态不得自动入账。
5. 原则性上线门槛：金额及关键日期在目标领域逐字段人工校准达到设定指标后，才开放“候选建议”；高风险税/社保/卡片/退款/法律解读必须逐项人工确认；任何免费模型不能满足可靠性时提供纯文本/手工输入，不以免费额度为理由牺牲准确性。
